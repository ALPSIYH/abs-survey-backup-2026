# 本機 26B 題目重排整合與 QA

日期：2026-07-24  
模型：`gemma4:26b-mlx`

## 結論

本機版已把 26B 模型接入題目搜尋的候選重排層。模型只接收既有題庫中
最多 20 個候選題，不能新增題號、不能產生統計數字，也不能直接執行分析。
模型不可用、逾時、輸出格式錯誤、信心不足或違反角色約束時，系統立即沿用
原本的確定性排序。

公開 Sites 版本不能存取使用者 Mac 上的 Ollama，因此 `/api/local-rerank`
在非本機網域固定回傳 503，公開站自動使用確定性題庫搜尋與雲端彙總統計。

## 執行流程

1. 確定性搜尋先從完整題庫取得候選並檢查統計量相容性。
2. 本機端確認 Ollama 中存在指定名稱與 digest 完全一致的 26B 模型。
3. 只把已存在的候選題號、英文題目、主題、分析型態與波次送給模型。
4. 只有 `high` confidence 且所有題號都屬於候選集時，才考慮採用重排。
5. 明示「自己的國家／own country」時，模型不得用具名外國題取代
   `[country]` 題；樣本國與評價對象不同時則允許具名外國題排在前面。
6. 任一檢查失敗都保留確定性排序，使用者仍可正常搜尋與分析。

## 模型能力邊界

26B 負責：

- 區分相近測量，例如民主程度、民主運作滿意度與民主意義。
- 區分影響程度與影響正負面。
- 區分受訪者所在地與題目實際評價的國家。
- 在候選題內調整相關性順序。

26B 不負責：

- 產生、修改或猜測題號。
- 判定不存在於題庫的題目。
- 產生 SQL、樣本數、平均數、比例或其他統計結果。
- 修改回答值、量表或資料涵蓋範圍。
- 在公開站遠端連回管理者電腦。

## 測試結果

測試矩陣共 33 個中英混合案例，涵蓋民主評價、政府信任、經濟評價、
中國與美國影響、社會信任、政治參與、選舉、公平、國族認同與
受訪地區／評價對象角色。

| 指標 | 結果 |
|---|---:|
| 26B 單獨語意正確 | 31 / 33（93.9%） |
| 26B + 生產護欄最終正確 | 33 / 33（100%） |
| 連續完整矩陣 | 3 輪均為 33 / 33 |
| 暖機後中位延遲 | 535 ms |
| 暖機後 P95 延遲 | 678 ms |
| 冷啟動觀察值 | 約 7.3 秒 |

兩組近乎同義的貧富差距題 `q163` 與 `q164.1` 視為可接受的等價候選。
模型仍會高信心誤判「日本受訪者評價自己的國家」，把 `q129` 排在
`q96` 前；角色護欄在每次測試中都拒絕此結果並保留 `q96`。這個錯誤被
明確記錄，沒有被當作模型成功。

## 瀏覽器驗證

- 根網址顯示英文版 Workspace。
- `?view=conversation&lang=zh-Hant` 顯示中文版對話分析。
- 直接開啟中文網址不再出現 React hydration mismatch。
- 「日本人認為中國對本國有多大影響」把 `q177` 排在 `q178` 前。
- 「日本受訪者認為自己的國家有多民主」把 `q96` 排在具名國家題前。
- 「韓國受訪者如何評價日本的民主程度」把 `q129` 排在 `q96` 前。

## 維運注意事項

- 本機啟動網站前，應先啟動 Ollama 並確認 `gemma4:26b-mlx` 可用。
- 專案要求 Node `>=22.13.0`；Node 20 會在建置工具使用 `fs.glob` 時失敗。
- 公開站顯示雲端題庫與統計狀態，不應聲稱本機模型已連線。
- 新增題目或改寫題目文字後，應重新執行 33 案例矩陣並補充新的刁鑽案例。
